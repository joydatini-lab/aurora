## Faits coûteux appris
- **`PS_ADMIN_TOKEN` n'est pas injectable ici.** Le mécanisme de secrets ne le connaît pas : la
  valeur reste vide même en le référençant dans la commande. Le check live est donc prouvé par
  `--remote-config` (fixtures), pas par un vrai fetch.
- **Forme réelle de la config distante** (source lue dans le paquet CLI, pas devinée) :
  `powersync/dist/api/cloud/fetch-cloud-config.js` → `{ config, syncRules }` où `syncRules` est le
  **texte** du sync-config (`instanceConfig.sync_rules`, type `string` dans
  `@powersync/management-types/dist/routes/manage-routes.d.ts:457`). Le script lit `syncRules` ET
  `sync_rules`.
- **`--project-id` est un no-op du CLI** : « Warning: --project-id is a no-op. Project ID is
  resolved automatically. » (`powersync fetch config --help`). On l'accepte pour l'affichage mais on
  ne le passe pas au CLI.
- `sync-config.yaml` = **11 flux / 33 tables** (compte confirmé : 11 clés à 2 espaces sous
  `streams:`, 33 `FROM` distincts). Les 33 tables ont `user_id` dans leur bloc `CREATE TABLE`.
- Aucun `JOIN` dans les requêtes (la seule occurrence de « JOIN » est dans un commentaire l.4).
- **`node_modules` absent** dans ce sandbox (clone isolé) → `eslint`/`pnpm -r typecheck` non
  lançables sans install. `node --check` suffit pour la syntaxe.
