## L5 — chemin vertical prouvé au navigateur (`2050277`)
Objectif : capture → commande kernel (AD-7) → tâche persistée → relecture réactive, **prouvé** et non affirmé.

Ce qui bloquait réellement (deux défauts, trouvés en instrumentant le navigateur, pas en lisant le code) :
1. **La ligne ne survivait pas au reload.** `EngineLocalStoreBridge.upsert` ne remplissait qu'un cache mémoire ;
   rien n'entrait dans la file CRUD native de PowerSync, donc rien n'était écrit en WASQLite/IndexedDB.
   Le commentaire d'`apply()` affirmait « point de durabilité » — c'était faux (fire-and-forget).
   Fix : `storeAdapter()` expose `upsertRow`/`deleteRow` ; `apply()` (et `applyOne`, et le chemin delete)
   attendent `flush()`. `await apply()` signifie maintenant « écrit ».
2. **La ligne persistait mais s'affichait au titre vide.** `SqliteQueryRepository` castait la ligne miroir.
   Le miroir dit `subject`, l'entité dit `title`. Fix : mapper de ligne injectable, branché sur le
   `mapTaskRow` déjà présent dans `data-session.ts` (jamais câblé). J'avais d'abord écrit un mapper en
   double dans `capture.ts` — corrigé : une seule source de vérité.

Chemin de diagnostic utile : `page.waitForSelector` échouait → j'ai d'abord cru à une course d'écriture,
puis le debug a montré `rows=1` mais `titres DOM: [""]` = la ligne existait, le mapping était faux.
Leçon : distinguer « la ligne n'est pas là » de « la ligne est là mais illisible » avant de patcher.

Trois autres corrections : `AuroraPowerSyncSchema.tables` est un tableau (`Object.keys` → index) ;
la branche d'identité locale de dev passe par `import()` dynamique + `import.meta.env.DEV` (chunk éliminé
du bundle prod, vérifié par grep : 0 occurrence) ; bannière dev gated pour élimination nette.
