## The guard and what it found
Two guards already compared schemas and both missed this: `client-schema-drift.test.ts`
compares the PowerSync client schema to the migrations (both SQL-side), and
`owner-module-coverage` reads table names, never columns. **Nothing compared
`packages/domain` — the AD-15 SSoT — to the migrations.**

D3 (confirmed against the LIVE catalog via `shttp_execute_sql`, not just the repo):
- `createTask` patches `tasks.tags` (tasks.ts:83) and `tasks.recurrence_rule` (tasks.ts:97)
- `createProject` (goals-projects.ts:164) and `updateProject` (goals-projects.ts:183) patch
  `projects.view_mode`
- None of the three exists in the live DB, `powersync-schema.ts`, or the generated SQLite DDL.
- Silent because `EngineLocalStoreBridge.upsert` (local-store-bridge.ts:67) is a **Map** keyed
  by column name: an unknown key is accepted, the screen renders, only the upstream PATCH fails
  (a queued-write failure, not a crash). The user sees their tags; the server never had them.

Also: 4 DELIBERATE renames, not bugs — `Project.title`→`projects.name` (goals-projects.ts:184),
`Task.title`→`tasks.subject` (tasks.ts:81), `Project.deadline`→`projects.end_date`,
`Task.timeSpentSec`→`tasks.actual_minutes`. And D2: `Artifact.kind` allows csv/text/code
(entities-artifact.ts:14-26) while `0007_artifact.sql:11` rejects them.

## Guard design notes (worth reusing)
- The `KNOWN_DEFECTS` list is **tripwired**: fixing a defect makes the test FAIL, forcing the
  entry's removal. A tolerated-defect list that cannot outlive its defect.
- Non-vacuity is asserted explicitly (`emittedColumns().length >= 3` per writer). That test
  caught a first regex-based version that silently extracted nothing from `createArtifact`.
  **Calling the code beats parsing its source.**
- Mutation-proven: deleting the `tasks.tags` entry yields
  "createTask writes tasks.tags — no such column".
